Words used all day, in plain language
  • Mirror: the corporate package proxy. Its hosted repos store the org's own packages; its proxy repo passes public npm packages inward.
  • Lifecycle hook: a script npm runs automatically around install, e.g. preinstall, before the package's code is even used.
  • Stage-1 / stage-2: the two halves of the payload. Stage-1 is the small loader inside the package; stage-2 is the real code, served by the attacker's server at run time.
  • IMDS: a cloud VM's metadata service (the thing that hands out cloud credentials to workloads).
  • Attestation / provenance: a signed statement that says which pipeline built a package.
  • Egress: outbound network connections from a machine to the internet.

  • It lives on the attacker's server (the collector) and can be swapped at any time WITHOUT touching any registry.
  • The published package stays identical, its behavior changes completely.
  • That is why real campaigns split loader from payload; every task below rides on it.

7.2 · The mutation replay (~5 min, the general lesson)

The mutate button republishes the same two-stage payload under a new package name and version, then makes the replay app consume it.

  • Indicators moved; behaviour did not.
  • IOC/string-based rules (matched a hostname, a package name, a hash) go dark.
  • Behavioural rules still fire. You see, on your own rule, which kind you wrote.

    hint · what you should see

    • [ioc-package-name] goes dark (the NAME moved).

7.3 · Read it out of the platform's own surfaces (~10 min)

The machine evidence you collected is only half the story. Two more surfaces recorded the whole campaign, and neither needs a shell:

  1. VPC flow logs (the network's memory): Dashboard → BLUE TEAM → VPC FLOW LOGS. Find the connection the dev machine made to your collector.
    hint · how to read a flow log
    • Each line is one observed connection: source, destination, port, decision.
    • Narrow the noise: filter to traffic whose DESTINATION is the collector host. The port is a field in each record: read it off the matching lines.
    • Full query UI: Grafana Explore → datasource Loki → {source="netflow"}.
    7.5Which destination port carried the exfil connections to your collector? (format: port number)

    9000: the collector. A flow-log entry from the dev machine to the collector on 9000 is the network-side footprint of every phone-home you caused today.

    netflow lines with dpt=9000 exist for the lab window.

  2. GitLab's credential audit surface (the platform's memory): Dashboard → BLUE TEAM → GITLAB TOKEN INVENTORY, or per project: Settings → Access Tokens. Every project access token is listed with its grant metadata: name, scopes, created, last used.
    hint · what to look for
    • The incident minted a long-lived credential during the break window: its grant shows up in a project's token inventory with a created timestamp inside that window.
    • Cross-check the clock: the incident ran while the room was on coffee (Task 5). "Last used" ties the token to the overnight harvest.
    7.6Which project access token did the incident mint, per the token inventory? (format: token name)

    runner-sync, a read_api token on acme/runner-tasks, created inside the break window and last used by the overnight harvest: the loot (Q6.3) and the platform's own inventory tell the same story from two sides. Task 6 revoked it through this exact surface.

7.4 · Re-attack under each hardening control, then rank honestly (~10 min)

Story · which control stops which attack

Each control blocks one of the paths you used today.

  • harden-allowlist makes the mirror reject package names ACME has never installed before: that blocks a fresh-named package from entering the build.
  • harden-ignore-scripts stops npm from running install scripts: that blocks the poisoned cowsay release.
  • harden-agent-trust makes the developer machine ignore repo-local hooks: that blocks the 3.2 attack.

Turn each control on with its buttons, re-run your attack, and write down which one would have caught you, and at which step.

  1. Tier 1, kill install-time execution.
    hint · the buttons and the replay
    • LAB CONTROLS → HARDENING TOGGLES → ignore-scripts ON.
    • Record the collector's /count before the replay. In GitLab, run a NEW pipeline for acme/replay-app on main; do not retry an old pipeline or run acme/shop-service for this check.
    • Why this target: replay-app only installs the poisoned dependency. shop-service runs npm test and imports its app dependencies; ignore-scripts blocks install lifecycle hooks, not code executed later at runtime.
    • Read /count again and compare the delta. Expected: install succeeds, the pipeline is green, and the count delta is 0.
    • Restore: ignore-scripts OFF.
    7.7With ignore-scripts ON, how many NEW collector hits does the acme/replay-app replay produce? (format: number)

    0, the install succeeds, the pipeline is green, the payload never runs.

    record the count, replay with ignore-scripts ON, then verify the count delta is 0 while the pipeline stays green.

  2. Tier 1, agent workspace trust: repo-local hooks suppressed (the ONLY Tier-1 control that touches the Task 3 path).
    hint · the button and the proof
    • LAB CONTROLS → agent-trust ON.
    • Proof with the headless trigger button: folder-open. Its output panel prints workspace trust: this folder is NOT trusted, hooks suppressed and NO new collector hit appears.
    • Why the button and not the editor: your VS Code session already trusted this folder once (trust is remembered per folder). The trust DECISION you made in Task 3 is exactly what this control models: an untrusted folder never auto-runs repo-local hooks.
    • Restore: agent-trust OFF.
  3. Tier 2, allowlist mirror: publish works, consumption dies. You can watch it bite with the buttons alone:
    hint · the buttons and the observable
    • Record the collector's /count, then set LAB CONTROLS → allowlist ON.
    • Press mutate + replay: it publishes the attack under a NEW name (c0wsayy) and makes the replay app install it.
    • Observable: the replay's install now 404s at the mirror (the replay pipeline fails on the new name) and the collector count stays at 0. The publish itself still succeeds: the gate only blocks consumption.
    • Restore: allowlist OFF.
  4. Show the state of every toggle: the HARDENING TOGGLES card shows all three pills (or press toggle status for the detailed printout).
    hint · what ON means here
    • The pills turn red/ON live after each button press; toggle status prints the same state as text in the output panel.
    • Leave the lab with all three OFF: that is the vulnerable baseline the next cohort starts from.

each toggle kills exactly its primitive; everything else still works. Rank: Tier 1 removes primitives (ignore-scripts, ephemeral runners, egress rules, short-lived OIDC, agent workspace-trust). Tier 2 narrows windows (cooldown/quarantine, protected branches, review of CI config, and provenance, which you proved does NOT stop this). Tier 3 detects after the fact.

Name a concrete change, the attack edge it blocks, and a verification test.

  1. Commit to one change, out loud, in writing: the control, the attack edge it blocks, and how you will verify it.
    hint · what makes a good commitment

    • Name the attack edge from TODAY it would have blocked.
    • Include the verification: how you would re-run the attack and see it fail.
